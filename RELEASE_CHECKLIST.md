# Release Checklist

Use this checklist before tagging a private beta or publishing a GitHub release asset.

## Release Scope

This release is a browser bridge for an already-open Overleaf editor tab. It is not a Git-token MCP server, not an Overleaf dashboard scraper, and not a full Overleaf CLI.

Supported:

- Chrome Extension loaded from `extension/`.
- Local MCP server from `server/overleaf-bridge-mcp.js`.
- Codex, Claude Code, Claude Desktop, and other MCP-capable clients.
- Current open project reads, current/named file reads, editor diagnostics, selection reads, hash-checked writes, unified patch application, compile status reading, snapshots, local patch logs, and snapshot restore.
- Connected-tab summaries, local project aliases, and in-memory target locks for multi-tab workflows.
- Manifest-backed local source mirror export, local mirror search, section lookup, and read-only mirror diff preview.
- Guarded mirror sync CLI wrapper for status, review-plan, pull-plan, push-plan, and strongly confirmed execute workflows.
- Read-only current source file and visible compile-log local exports.
- Visible artifact discovery/export, upload workflow inspection, download workflow inspection, visible comment inspection, non-mutating comment action planning, non-mutating file-operation planning, and guarded file-operation execution with confirmation checks.
- Free Overleaf projects that can be opened in the browser editor.
- Self-hosted or custom-domain Overleaf editor tabs through a generated local extension copy under `.runtime/extension-builds/`.

Not supported in this release:

- Overleaf cookies, session extraction, passwords, OAuth tokens, or Git tokens.
- Account dashboard enumeration or background project scraping.
- Overleaf Git integration, `git remote`, `pull`, `push`, or full bidirectional sync.
- Account-level project creation, project zip upload, unattended project zip download, automated local file upload, unattended live comment mutation, folder moves, full Overleaf server administration, or unattended live file management mutations.
- Unattended real manuscript edits without `projectTitle`, `expectedFileName`, `beforeHash`, and `reason`.

## Version Consistency

Keep these values aligned:

- `package.json` `version`
- `extension/manifest.json` `version`
- `serverInfo.version` in `server/overleaf-bridge-mcp.js`
- `BRIDGE_VERSION` in `extension/contentScript.js`
- `CHANGELOG.md`

## Offline Gate

Run from the repository root:

```powershell
npm run release:check
npm run first-run
npm run live:verify -- --allow-offline
npm run live:suite -- --allow-no-page
npm run config:mcp
npm run extension:build -- --overleaf-origin https://overleaf.example.com
npm run package:extension
npm run package:npm
npm run repo:metadata
npm run release:assets
npm run release:candidate
npm run release:decision
npm run sync:mirror -- --list
npm run release:preflight
```

Pass criteria:

- `doctor` passes.
- `tests/server.test.js` passes.
- `npm run first-run` reports `ok:true` and generated files remain under ignored `.runtime/first-run/`.
- `npm run live:verify -- --allow-offline` reports `ok:true` for offline release prep, or live page/version failures when a bridge is running and stale.
- `npm run live:suite -- --allow-no-page` reports `blocked_no_page` when the bridge is healthy but no project tab is connected, or runs all safe metadata/read-only/plan gates when a tab is connected.
- `.runtime/generated-configs/codex-mcp.toml` and `.runtime/generated-configs/mcp-launch.json` are generated by `npm run config:mcp` and remain untracked.
- `.runtime/extension-builds/` can be generated by `npm run extension:build -- --overleaf-origin https://overleaf.example.com` and remains untracked.
- Extension package is created under `dist/`.
- The package contains only release extension files: `manifest.json`, `contentScript.js`, `pageBridge.js`, `popup.html`, and `popup.js`.
- npm package dry run includes the CLI entrypoint, server, extension, config templates, docs, README, license, and `llms.txt`.
- Package CLI helper discovery works: `node bin/overleaf-browser-bridge.js --list-commands` and `node bin/overleaf-browser-bridge.js live-suite --list`.
- npm package dry run excludes `STATE.md`, `.runtime/`, `dist/`, `node_modules/`, `local-notes/`, tokens, aliases, and snapshots.
- `npm run repo:metadata` reports `ok:true`, `published:false`, and an empty `publishActionsPerformed` list.
- `dist/release-v<version>/release-assets-manifest.json` exists after `npm run release:assets`.
- `dist/release-v<version>/SHA256SUMS.txt` includes the extension zip hash.
- `npm run release:candidate` reports `releaseCandidate:true`, `published:false`, and an empty `publishActionsPerformed` list.
- `npm run release:decision` reports `readyForHumanReleaseDecision:true`, `published:false`, and an empty `publishActionsPerformed` list.
- `npm run sync:mirror -- --list` reports `defaultIncludesDiffText:false`, no automatic bidirectional sync, and confirmation-required execute behavior.
- `npm run release:preflight` reports `ok:true`, `published:false`, and an empty `publishActionsPerformed` list.
- No local backup files, `.runtime/`, snapshots, local mirrors, private manuscript text, tokens, cookies, or machine-specific paths are included.

## Chrome And Overleaf Live Gate

Load or update the unpacked extension from:

```text
<ABSOLUTE_REPO_PATH>\extension
```

Open or reload a target Overleaf project tab, then run:

```powershell
npm run live:verify
npm run live:suite
node scripts/live-smoke-test.js
node scripts/live-noop-release-test.js
node scripts/live-section-noop-test.js
node scripts/live-context-budget-test.js
node scripts/live-target-lock-test.js
node scripts/live-mirror-test.js
node scripts/live-export-test.js
node scripts/live-artifact-inventory-test.js
node scripts/live-visible-artifact-export-test.js
node scripts/live-file-operation-ui-test.js
node scripts/live-upload-workflow-test.js
node scripts/live-download-workflow-test.js
node scripts/live-comments-inspection-test.js
node scripts/live-prepare-comment-action-test.js
node scripts/live-prepare-file-operation-test.js
```

Pass criteria:

- `health_check` reports at least one connected Overleaf page.
- `paper_context` returns project metadata and file tree data when the file tree is open.
- `read_current_file` returns metadata and hash for the current file.
- `get_editor_diagnostics` returns a diagnostics result without dumping manuscript text.
- No-op `replace_file`, no-op `apply_patch_to_file`, and no-op `restore_from_snapshot` preserve the original hash.
- `get_sections`, `get_section_content`, and no-op `replace_section` work on the current file and preserve the original hash.
- `read_file_range`, `read_file_since_hash`, and `contextBudget` summary reads return bounded metadata and preserve the current hash.
- `lock_target_project` can lock the intended connected tab; locked calls reject if the tab later points at a different project.
- `sync_project_snapshot` writes `manifest.json` and latest-manifest metadata; `find_in_project_mirror`, `preview_mirror_diff`, `prepare_mirror_sync_plan`, and `execute_mirror_sync_plan` cover local mirror refresh plus update-only mirror-to-Overleaf write-back with fresh hash checks.
- `export_current_file` and `export_compile_log` write local exports without creating, renaming, deleting, uploading, or overwriting Overleaf files.
- `list_visible_artifacts` and `export_artifact_inventory` produce metadata-only artifact inventories without downloading private output files.
- `export_visible_artifact` writes at most one selected visible downloadable artifact to a private local export file, with byte limit, hash, MIME type, manifest, and no raw private URL or cookie output.
- `inspect_file_operation_ui` reports file-management UI readiness without clicking or mutating Overleaf files.
- `inspect_upload_workflow` reports upload/image workflow readiness, accepted file constraints, drop zones, image candidates, and the user file-picker boundary without opening pickers or uploading files.
- `inspect_download_workflow` reports download/export workflow readiness, source-file candidates, artifact candidates, redacted URLs, and the user-confirmation boundary without clicking controls or downloading project ZIPs.
- `inspect_visible_comments` reports visible comment/review-thread metadata and action-control counts without replying, resolving, reopening, deleting, or clicking collaboration controls.
- `prepare_comment_action` creates non-mutating confirmation plans with thread-list hash, selected thread signature, exact confirmation phrase, and no comment mutation.
- `execute_comment_action` passes offline fake-client tests for resolve, reopen, delete-comment, and wrong confirmation phrase rejection; live comment mutation is not part of the default release gate.
- `prepare_file_operation` creates non-mutating confirmation plans with file-list hash and exact confirmation phrase, without executing operations.
- `execute_file_operation` passes offline fake-client tests for create, rename, delete, and wrong confirmation phrase rejection; live file mutation is not part of the default release gate.
- `compile_and_read_log` returns visible Overleaf compile status or log summary.
- If the currently open project has existing LaTeX errors, document them as project status, not bridge failure, when the no-op hash stays unchanged.

Use [LIVE_TEST_CHECKLIST.md](LIVE_TEST_CHECKLIST.md) for manual setup details and write-test alternatives.

## Privacy Gate

Before publishing, confirm:

- The repository does not include `.runtime/`, `dist/`, local notes, local mirrors, snapshots, patch logs, or generated archives.
- Docs use placeholders such as `<ABSOLUTE_REPO_PATH>` rather than real local paths.
- No Overleaf cookies, sessions, Git tokens, passwords, OAuth tokens, private keys, or project secrets appear in tracked files.
- The release zip is built from the whitelisted extension file list, not by compressing the entire `extension/` directory blindly.

## Release Notes

Every release note should state:

- This bridge works through an already-open browser tab.
- It does not require Overleaf Premium Git sync, cookies, sessions, or Git tokens.
- It is intended for AI agents that need safe local Overleaf editor access.
- Write tools require explicit project, file, hash, and reason fields.
